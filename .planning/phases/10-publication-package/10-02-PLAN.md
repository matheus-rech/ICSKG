Create analysis/data_dictionary.py with these functions:

1. **generate_data_dictionary(db_path, out_dir) -> Path** (PUBL-07)
   - Connect to SQLite, enumerate all tables via `SELECT name FROM sqlite_master WHERE type='table'`
   - For each table, get columns via `PRAGMA table_info({table})`
   - For each column, produce a row with: table, column_name, sqlite_type, is_primary_key, source, definition, unit, coverage_years, missingness_rate
   - Populate source/definition/unit from these lookups:
     a. CIMI_DIMENSIONS dict in build_database_v3.py for dimension_metadata/dimension_scores columns
     b. LCOGS_METADATA list in compute_lcogs.py for lcogs_indicators columns
     c. DIMENSION_MAP in compute_dimensions.py for municipal_health source columns
     d. Hardcoded fallback dict for remaining standard columns (cod_ibge, year, region, state_uf, name, population, etc.)
   - For missingness_rate: query SQLite for each column in municipal_health and dimension_scores: `SELECT COUNT(*) - COUNT({col}) as n_missing, COUNT(*) as n_total FROM {table}`; compute pct_missing = n_missing/n_total*100
   - coverage_years: "2015-2023" for most; "2010" for idhm (D3), "2022" for pct_sanitation_adequate (D5)
   - Save to results/data_dictionary.csv
   - Log summary: N tables, N columns documented, N with missingness > 0

2. **validate_dictionary_against_schema(db_path, dict_path) -> dict** (validation)
   - Load the data dictionary CSV
   - Connect to SQLite, get all table.column pairs
   - Compare: are there columns in SQLite not in the dictionary? Vice versa?
   - Return {valid: bool, missing_from_dict: [...], extra_in_dict: [...], tables_checked: int, columns_checked: int}
   - Log validation result

3. **main(argv) -> int** CLI entry point
   - Arguments: --db-path, --out-dir
   - Call generate_data_dictionary then validate_dictionary_against_schema
   - Return 1 if validation fails (missing columns)

<objective>
Make `build_database_v3` capable of fetching its inputs from the HuggingFace Dataset published in Phase 11.1, and make any future "phantom database" failure mode impossible by adding fail-loud guards in two places.

Purpose: The current CI failure is a symptom of two problems — (a) the v3 builder has no way to acquire processed data when the local directory is empty, and (b) when the data IS empty, the failure surfaces as a cryptic `KeyError: 'variable'` deep inside a reporting helper rather than a clear "no data" error at the root. Phase 11.2 fixes both. After this plan lands, the workflow `python -m database.build_database_v3 --from-hf v0.1.0` succeeds end-to-end on a clean machine, and `python -m database.build_database_v3 --processed-dir /empty/dir` fails immediately with a meaningful RuntimeError that names the missing data sources.

Output: A working `--from-hf` integration, two layered fail-loud guards, and a committed smoke fixture tree that exercises the entire pipeline in <5 seconds for CI and unit tests.
</objective>

<gotchas>
- The METADATA_COLS set in the fail-loud guard must match the actual metadata column names produced by `database/assemble_panel.py`. Read assemble_panel.py before writing the guard to confirm. Best approach: import a constant from assemble_panel rather than hardcoding.
- The smoke fixture must be deterministic — every parquet file should have stable byte-identical output across runs. Use a fixed pandas write order, no timestamps, no random data.
- The fixture's manifest.json should mirror the schema from Phase 11.1 publish_to_hf so the same `verify_manifest()` function works on both real HF data and the smoke fixture.
- `huggingface_hub.snapshot_download` caches under ~/.cache/huggingface/hub/ by default. CI must reuse this cache via actions/cache (Phase 11.3). The fetcher should NOT delete the cache between calls.
- snapshot_download with local_dir_use_symlinks=False is required for: (a) Windows replicators, (b) CI runners that may not have symlink permissions in some directories, (c) deterministic SHA256 verification (symlinked files SHA256 ≠ source SHA256).
- The fail-loud RuntimeError must come BEFORE any further processing (before deflate_ipca, before impute_ifgf_mice). Otherwise we waste compute and produce confusing partial state.
- The schema-pin in generate_missingness_report MUST be done with `pd.DataFrame(rows, columns=REPORT_COLUMNS)` — NOT `pd.DataFrame(rows).reindex(columns=REPORT_COLUMNS)` because reindex creates NaN-filled columns which then break sort_values on dtype mismatches.
- pytest.raises(RuntimeError, match="Refusing to build a phantom database") is the right pattern to lock the error message contract.
- When testing the --from-hf flag, mock snapshot_download with `monkeypatch.setattr("database.fetch_processed_data.snapshot_download", fake)` to avoid network in CI. The test should verify the fetch is called with the right args, not that real HF works (that's an integration test, deferred to Phase 11.3).

1. **Create database/fetch_processed_data.py** with these functions:

   **`fetch_processed_tree(repo_id: str, revision: str, target_dir: Path, *, hf_token: str | None = None, allow_patterns: list[str] | None = None) -> Path`**
   - If `target_dir` already contains a manifest.json with matching revision, return target_dir without re-downloading (cache hit)
   - Otherwise, call `snapshot_download(repo_id=repo_id, repo_type="dataset", revision=revision, local_dir=str(target_dir), local_dir_use_symlinks=False, allow_patterns=allow_patterns or ["**/*.parquet", "manifest.json", "README.md"], token=hf_token)`
   - After download, call `verify_manifest(target_dir)`
   - Returns `target_dir` (for chaining)
   - Logs every step with %-style logging

   **`verify_manifest(local_dir: Path) -> dict`**
   - Reads `local_dir/manifest.json`
   - For each entry in `manifest["tables"]`, opens the parquet file and:
     - Computes its SHA256
     - Compares against `entry["sha256"]` from manifest
     - On mismatch, raises `RuntimeError(f"SHA256 mismatch for {parquet_path}: expected {expected}, got {actual}")`
     - Compares actual row count (via pyarrow.parquet.ParquetFile.metadata.num_rows) against `entry["row_count"]`
     - On mismatch, raises `RuntimeError`
   - Returns the manifest dict on success
   - This guards against partial downloads, cache corruption, and tampered files

   **`materialize_to_processed_dir(parquet_tree_dir: Path, processed_dir: Path) -> None`**
   - Copies parquet files from the HF tree shape (panel/, dimensions/, lcogs/, source_tables/) into the flat `data_sources/processed/{source_name}/` shape that `assemble_panel.py` expects
   - This is a translation layer because Phase 11.1 publishes a namespaced tree but the existing assemble_panel reads from per-source flat directories
   - Mapping rules:
     - `source_tables/sih_aggregated.parquet` → `processed_dir/sih/sih_aggregated.parquet`
     - `source_tables/cnes_workforce.parquet` → `processed_dir/cnes/workforce.parquet`
     - `source_tables/ans_beneficiaries.parquet` → `processed_dir/ans/beneficiaries.parquet`
     - `source_tables/ifgf_index.parquet` → `processed_dir/ifgf/ifgf_index.parquet`
     - `source_tables/siops_*.parquet` → `processed_dir/siops/...`
     - `source_tables/ibge_*.parquet` → `processed_dir/sidra/...`
     - `source_tables/ipea_idhm.parquet` → `processed_dir/ipea_idhm/idhm.parquet`
     - `source_tables/census_sanitation.parquet` → `processed_dir/census_sanitation/sanitation.parquet`
     - The panel/dimensions/lcogs/ namespaces are already-built artifacts and bypass assemble_panel — they're consumed directly by build_database_v3 in the materialized output. Document this in a docstring.
   - Logs every file copied
   - Raises `FileNotFoundError` if a required mapping is missing from the parquet tree

   **`main(argv: list[str] | None = None) -> int`** CLI entry point:
   - `--repo-id` (default `matheus-rech/icskg-br-processed`)
   - `--revision` (required)
   - `--target-dir` (default `~/.cache/icskg/hf-snapshots/{revision}`)

   - `--verify-only` (skip download, just verify an existing tree)
   - Wires `fetch_processed_tree` → `materialize_to_processed_dir` (if --processed-dir given)
   - Returns 0 on success, 1 on verification failure
